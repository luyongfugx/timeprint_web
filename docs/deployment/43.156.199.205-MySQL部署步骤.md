# 43.156.199.205：Timeprint MySQL 部署步骤

目标是让当前 Web 服务通过 Prisma 访问这台机器上的 MySQL。以下默认端口 3306、独立业务库名 timeprint_share_wm；端口和库名可根据实际部署替换。尚未连接该服务器，版本、账号、TLS、现有表及网络配置都需要先检查。本文只交付操作步骤和 SQL，没有执行远程数据库操作。按当前安排不导出 Supabase。

## 1. 先确认部署位置和连接来源

| Web 服务在哪里 | 数据库地址 | MySQL 账号 Host 与网络设置 |
| --- | --- | --- |
| 与 MySQL 同机，非容器 | 优先 127.0.0.1:3306 | 本地账号，按实际 CURRENT_USER() 匹配检查；无需向公网开放 3306 |
| 同机容器 | 容器可达的宿主机地址/内部网络名 | 允许实际容器来源；容器里的 127.0.0.1 是容器自身 |
| 同 VPC 的另一台服务器 | 优先数据库内网地址 | 只允许应用和迁移机器的内网来源 |
| 其他网络服务器 | 43.156.199.205:3306 | 只允许确定的出口 IP，并使用验证证书的 TLS |

下文 SQL 中的 APP_SOURCE_IP 是 MySQL 实际看到的客户端来源地址，**不是固定填写数据库的 43.156.199.205**。迁移命令默认在同一应用机器执行；若另有迁移机器，迁移账号 Host 单独替换为它的来源地址。不要直接使用 '%' 作为生产开放范围。

跨机器需要 MySQL 监听可达接口，并在服务器防火墙和云安全组中允许这些指定来源访问数据库端口。不要直接照抄某个系统的配置文件路径或重启命令；先确认这台机器是系统服务还是 Docker，以及当前其他应用是否共用实例。

## 2. 在数据库服务器登录管理员并检查实例

在 43.156.199.205 的终端使用已有数据库管理员登录，不必为本项目开放远程 root：

```bash
MYSQL_HISTFILE=/dev/null mysql -u root -p
```

如果现有管理员不是 root，请替换用户名。密码通过提示输入。执行：

```sql
SELECT VERSION() AS mysql_version;
SELECT @@port, @@hostname, @@global.time_zone, @@session.time_zone,
       @@character_set_server, @@collation_server;
SELECT @@sql_mode;
SHOW VARIABLES LIKE 'have_ssl';
SHOW VARIABLES LIKE 'bind_address';
SELECT SCHEMA_NAME FROM information_schema.SCHEMATA WHERE SCHEMA_NAME = 'timeprint_share_wm';
SELECT TABLE_NAME, TABLE_TYPE, ENGINE
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'timeprint_share_wm'
ORDER BY TABLE_NAME;
```

要求 MySQL 8.0.16+，本项目实测版本为 8.0.30，业务表使用 InnoDB 和 utf8mb4。不能使用 MySQL 5.7 或把 MariaDB 当作已验证替代。脚本目前仅检查主版本，8.0 的补丁版本需在此人工核对。

分支判断：

- timeprint_share_wm 不存在或完全为空：执行下面的首次部署流程。
- 已有旧版 watermarks_share_links、没有 contract_version：先备份并核对结构，再使用项目迁移脚本。不要执行空库 SQL。
- 已经存在 contract_version：不要重复运行首次迁移。可能已经部署或迁移中断，先核对完整表/视图及约束。后续普通代码部署不需要再次建表。

日期按 UTC 保存。应用事务会设置 session UTC，当前新表默认值使用 UTC_TIMESTAMP；不要为了本应用随意修改整个实例的全局时区。旧数据原有时区需另行确认。

## 3. 如库内已有数据，先备份 MySQL

这一项只针对将要变更的 MySQL 库，与暂不执行的 Supabase 导出无关。可在数据库服务器运行，使用具备相应读取权限的备份/管理员账号：

```bash
umask 077
mkdir -p "$HOME/timeprint-db-backups"
mysqldump -u root -p --single-transaction --quick --hex-blob \
  --no-tablespaces --set-gtid-purged=OFF \
  --databases timeprint_share_wm \
  > "$HOME/timeprint-db-backups/timeprint-before-deploy-$(date +%Y%m%d-%H%M%S).sql"
```

检查退出码和备份文件，并在隔离库验证恢复。备份期间不要并行执行 DDL。若 timeprint_share_wm 尚不存在，跳过此步。不要将备份放入项目 Git 仓库。

## 4. 建库和账号

由数据库管理员执行。建议创建独立 timeprint_share_wm 库，不复用其他产品的业务库：

```sql
CREATE DATABASE IF NOT EXISTS timeprint_share_wm
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

下面是跨机器 TLS 连接的账号示例，执行前替换 APP_SOURCE_IP 和两个独立强密码。账号若已存在，应先 SHOW GRANTS 检查，不要盲目覆盖密码。

```sql
CREATE USER 'timeprint_migrator'@'APP_SOURCE_IP'
  IDENTIFIED BY 'REPLACE_WITH_MIGRATION_PASSWORD'
  REQUIRE SSL;

CREATE USER 'timeprint_app'@'APP_SOURCE_IP'
  IDENTIFIED BY 'REPLACE_WITH_APP_PASSWORD'
  REQUIRE SSL;

GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX,
      REFERENCES, CREATE VIEW, SHOW VIEW
ON timeprint_share_wm.* TO 'timeprint_migrator'@'APP_SOURCE_IP';
```

同机且仅使用可信本地连接时，替换为实际匹配的本地 Host，并可省略 REQUIRE SSL；本地配置也应与之匹配。公网连接必须先配置有效 TLS，不用 accept_invalid_certs 绕过验证。若证书不包含 43.156.199.205 的 IP SAN，使用指向该实例、且与证书匹配的数据库域名。

CREATE USER 与 GRANT 直接生效，不需要 FLUSH PRIVILEGES。账号按用户名与来源 Host 区分，参考 [MySQL 账号和授权说明](https://dev.mysql.com/doc/refman/8.0/en/creating-accounts.html)。

## 5. 在部署机器生成 Prisma Client

进入实际项目目录，使用 Node.js 22：

```bash
npm ci --include=dev
npm run prisma:generate
npm run prisma:validate
```

这几个命令不建表。安装/构建阶段要保留 Prisma CLI 开发依赖。如果本机 npm 默认缓存权限有问题，可在 npm ci 后添加 `--cache "$HOME/.cache/timeprint-npm"`。

## 6. 首次建表：两种方式二选一

### 方式 A：项目迁移脚本（推荐）

在部署项目根目录准备 `.env.migration.local`，仅包含迁移连接，权限设为 600：

```dotenv
DATABASE_URL="mysql://timeprint_migrator:URL_ENCODED_MIGRATION_PASSWORD@43.156.199.205:3306/timeprint_share_wm?connection_limit=1&sslaccept=strict&sslcert=/absolute/path/mysql-ca.pem"
```

用户名/密码有特殊字符时做 URL 编码；CA 文件路径替换为部署机器实际路径，使用系统已信任证书时可按情况省略 sslcert。文件名以 .local 结尾，已被项目 .gitignore 忽略。

```bash
chmod 600 .env.migration.local
# 排除进程里已有 DATABASE_URL 的覆盖，确保使用这个迁移配置。
env -u DATABASE_URL node --env-file=.env.migration.local scripts/migrate-templates.mjs
# 上面预检查确认目标库、版本、字段后，再执行：
env -u DATABASE_URL node --env-file=.env.migration.local scripts/migrate-templates.mjs --apply
# 然后初始化邮箱密码管理员表及默认账号（已有账号不会重置）：
env -u DATABASE_URL node --env-file=.env.migration.local scripts/migrate-admin-login.mjs
```

预检查输出字段类型，不输出用户内容。空库会自动创建基础分享表及新版对象；旧基础表会根据原主键类型建立关联字段。SQL 的 MySQL DDL 隐式提交，中途失败后不能假定整体回滚，需检查已成功的语句再修复，不能直接重跑或删库。

### 方式 B：直接执行完整空库 SQL

仅适用于空的 timeprint_share_wm 库。已提供没有占位主键类型的完整建表文件：

[timeprint-empty-database.sql](./timeprint-empty-database.sql)

它包含 `USE timeprint_share_wm`、基础表、ALTER、关联表、索引、约束及两个视图。通过具备建表权限的管理员或迁移账号导入，例如在数据库服务器本机：

```bash
mysql -u root -p timeprint_share_wm < /path/to/timeprint-empty-database.sql
```

**不要同时执行方式 A 和 B，也不要将该文件用于已有业务表的库。** 项目源迁移文件中的 `{{TEMPLATE_ID_TYPE}}` 由脚本替换；不要原样将含占位符的源文件导入。

## 7. 给应用账号授权

建表成功后，由管理员执行。先将 APP_SOURCE_IP 替换为第 4 步相同的实际来源：

```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.watermarks_share_links TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_assets TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_upload_sessions TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_publish_requests TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_uses TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_reports TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_requests TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_search_snapshots TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_trending_terms TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, UPDATE, DELETE ON timeprint_share_wm.template_rate_limits TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT ON timeprint_share_wm.template_moderation_actions TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT ON timeprint_share_wm.admin_accounts TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT, INSERT, DELETE ON timeprint_share_wm.admin_sessions TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT ON timeprint_share_wm.template_records TO 'timeprint_app'@'APP_SOURCE_IP';
GRANT SELECT ON timeprint_share_wm.template_asset_records TO 'timeprint_app'@'APP_SOURCE_IP';

SHOW GRANTS FOR 'timeprint_app'@'APP_SOURCE_IP';
SHOW GRANTS FOR 'timeprint_migrator'@'APP_SOURCE_IP';
```

应用不需要 CREATE/ALTER/DROP/GRANT 权限，也不应使用 root 或迁移账号启动。

迁移文件创建的视图使用默认 DEFINER。先确认：

```sql
SELECT TABLE_NAME, DEFINER, SECURITY_TYPE
FROM information_schema.VIEWS
WHERE TABLE_SCHEMA='timeprint_share_wm';
```

若 DEFINER 是迁移账号，不能直接删除这个账号或撤销视图需要的底表 SELECT 权限。迁移完成后可以锁定其登录，同时保留账号和视图读取权限：

```sql
ALTER USER 'timeprint_migrator'@'APP_SOURCE_IP' ACCOUNT LOCK;
```

后续确有结构迁移时，由管理员解锁 `ACCOUNT UNLOCK` 后执行，完成后再锁定。也可以在单独审核后改用 SQL SECURITY INVOKER 视图；本次步骤不自动改写它们。

## 8. 默认管理员和可选热词

后台现在从 MySQL admin_accounts 校验邮箱和密码，不再使用 Supabase Auth。第 6 步的迁移/空库 SQL 已初始化默认管理员 `luyongfugx@gmail.com`，初始密码为本次指定的密码。SQL 中仅包含带随机盐的 scrypt 哈希，不保存明文。重复执行初始化不会重置已有密码、角色或停用状态。

```sql
USE timeprint_share_wm;
SELECT id, email, role, enabled, created_at FROM admin_accounts;
-- 需要停用账号时执行（将立即阻止该账号已有会话继续访问）：
-- UPDATE admin_accounts SET enabled=0 WHERE email='目标管理员邮箱';
```

数据库账号 timeprint_app 只读 admin_accounts，不能自行创建或提升管理员。修改密码、手工增补管理员需由迁移/管理账号执行；详细操作见 [管理员登录说明](../templates/admin-login.md)。旧 template_admins 表仅为历史兼容保留，不再作为权限来源。无公开注册入口。

可选热词示例。iOS 当前中文目录语言使用 zh，下面同时提供 zh-CN 示例；热词是精确 locale 查询，不会自动做语言前缀匹配：

```sql
INSERT INTO template_trending_terms (id, term, locale, sort_order, enabled)
VALUES
```

热词不会创建水印内容，空库的公开列表仍为空。不要为测试在生产库伪造私人模板或把旧记录批量设置为公开。

管理员在目标库执行：

```sql
SELECT TABLE_TYPE, COUNT(*) AS object_count
FROM information_schema.TABLES
WHERE TABLE_SCHEMA=DATABASE()

SHOW CREATE VIEW template_asset_records;
SELECT CONSTRAINT_NAME, CONSTRAINT_TYPE

  AND TABLE_NAME='watermarks_share_links';
SELECT COUNT(*) AS templates FROM template_records;

```

再从应用机器，以应用账号测试跨机连接：

```bash
mysql -h 43.156.199.205 -P 3306 -u timeprint_app -p \
  --ssl-mode=VERIFY_IDENTITY --ssl-ca=/absolute/path/mysql-ca.pem timeprint_share_wm
```

```sql
SELECT DATABASE(), CURRENT_USER(), VERSION();
```

TLS 证书必须与 -h 指定的主机/IP 匹配。若失败，先修复证书、账号来源、端口或网络，不要把应用换成 root 或关闭公网证书校验。

## 10. 配置应用并部署

应用 `.env.local` / 部署秘密配置使用 timeprint_app，而不是 migrator：

```dotenv
DATABASE_URL="mysql://timeprint_app:URL_ENCODED_APP_PASSWORD@43.156.199.205:3306/timeprint_share_wm?connection_limit=10&pool_timeout=30&sslaccept=strict&sslcert=/absolute/path/mysql-ca.pem"

TEMPLATE_PUBLIC_ENABLED=false
TEMPLATE_PRIVATE_ENABLED=false
TEMPLATE_SEARCH_ENABLED=false
TEMPLATE_REPORT_ENABLED=false
```

若应用与 MySQL 同机并使用可信本地 TCP，示例可调整为 `mysql://timeprint_app:URL_ENCODED_APP_PASSWORD@127.0.0.1:3306/timeprint_share_wm?connection_limit=10&pool_timeout=30`，并使用匹配的本地账号。不要把私密 URL 发到聊天或 Git。

DATABASE_URL 非空时优先于 TEMPLATE_MYSQL_*；删除或同步部署系统中旧的 DATABASE_URL，避免环境变量覆盖文件。修改连接配置后需要重新启动应用进程。

本次 MySQL 只负责业务数据；启用分享还需要 `.env.templates.example` 中 COS SecretId/SecretKey、桶和独立目录、两个至少 32 字符的 HMAC/游标签名密钥及域名配置。数据库建好但未配置 Storage 时，不能正常发布水印。

```bash
npm run prisma:generate
npm run prisma:validate
npm run build
npm run start
```

按实际进程管理器启动或重启服务。先检查 capabilities 和后台登录，再在受控联调完成后按 REPORT → PUBLIC → PRIVATE → SEARCH 的依赖顺序启用并重启。不要在生产库运行 `test:templates:mysql`，它会清理测试业务数据。

## 11. 已有 Supabase 数据如何处理

现在按要求暂不导出，因此此处新库不会自动获得旧分享数据。若将线上立即切换到这个空库，旧分享码在新库查不到。正式切换前需选择并完成：保留旧服务读取直到迁移完成，或明确接受旧分享暂不可用。

当前代码没有“查 MySQL 不到再查 Supabase”的自动回退。后续迁移需保留旧 ID、share_code、created_at、expire_time 和资源源 URL，核对时区/主键类型后再启用旧码访问。不能把 PostgreSQL 导出 SQL 直接当 MySQL SQL 执行。

## 12. 后续每次部署是否还要建表

普通代码更新只需安装依赖、生成 Prisma Client、构建并重启；不重复首次建表和管理员初始化。新增结构变更时先备份，再执行专门增量迁移。

当前项目没有 Prisma Migrate 基线历史，仍使用已有 SQL 迁移；不要使用 `prisma db push`、`migrate reset` 或直接在生产执行 `migrate dev`。实际目标结构与提交模型不一致时，在受控环境反向读取并审查 schema，再生成客户端，不能用测试库模型强制覆盖生产表。
