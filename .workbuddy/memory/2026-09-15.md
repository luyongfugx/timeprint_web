## 旧版 POST /api/applink 返回 422 的定位（无服务端日志，靠线上 DB 反推）

- 现象：iOS 旧版创建分享 → `POST https://wm.timeprint.net/api/applink` 返回 422，body 仅
  `{"error":"The request could not be completed."}`。该文案是 `errors.ts` 的默认 message，说明抛出的是
  未带自定义文案的 `TemplateError`。
- 已排除：zod 校验失败（400 "Please check the request fields."）、`The resource source is not allowed.`
  （说明 `TEMPLATE_ALLOWED_LEGACY_ASSET_HOSTS` 与路径正则已通过）、503（PUBLIC 开关已开）、429（限流另有文案）。
- 线上就是本仓库代码：`GET /api/applink/v2/capabilities` → visibility=[public,private]、search/report=true；
  `POST /api/applink` 空 body → 400 "Please check the request fields."。
- DB 取证（只读）：08:58:08 那次请求留下了 `template_upload_sessions` 行（00:58:09 UTC），state=`open`、
  cover_asset_id/payload_asset_id 全为 NULL；同一小时 29 个会话全 open，`template_assets` 无任何 staging 行。
  → 失败发生在 **fetchLegacy 拉取封面期间/之前**，一个资源都没注册；且是环境性、系统性的（不是这条 payload 特有）。
- 本机复现（scripts/diagnose-legacy-applink.ts）：cover 1080x464/68KB、json 2.6KB/15 items、logo 均可下载，
  legacyURL / parsePayload / imageFields 全通过 → 资源内容没问题。剩余嫌疑集中在服务端网络的 DNS 公网校验：
  本机 VPN 把 COS 域名解析成 198.18.0.77（fake-IP），而 `fetchLegacy` 只对 198.18/198.19 段走 dns.google 兜底，
  且兜底本身依赖 dns.google 可达（境内服务器不可达）。需线上日志确认。

## 代码改动
